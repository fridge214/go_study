# Go 变量逃逸（Escape Analysis）教程

## 1. 什么是变量逃逸
在 Go 中，编译器会做**逃逸分析**：判断一个变量应该分配在栈（stack）还是堆（heap）。

- 不逃逸：变量生命周期只在当前函数内，通常分配在栈上。
- 逃逸：变量在函数外仍可能被使用，通常分配在堆上。

一句话理解：**超出当前函数生命周期还要活着的变量，通常会逃逸到堆上。**

## 2. 为什么要关心
堆分配会带来：
- 更多内存分配开销
- 更大 GC（垃圾回收）压力
- 更不稳定的延迟（特别是高并发服务）

所以在性能敏感代码里，减少不必要逃逸通常能提升吞吐和降低延迟。

## 3. 常见逃逸场景

### 场景 A：返回局部变量地址（会逃逸）
```go
func newIntPtr() *int {
    x := 10
    return &x // x 逃逸到堆
}
```

### 场景 B：只在函数内使用（通常不逃逸）
```go
func localCompute() int {
    x := 10
    return x + 1 // x 通常在栈上
}
```

### 场景 C：装箱到 interface（可能逃逸）
```go
func toInterface() any {
    x := 42
    return x // 可能触发逃逸（与编译器优化有关）
}
```

### 场景 D：闭包捕获外部变量（常见逃逸）
```go
func makeAdder(base int) func(int) int {
    return func(v int) int {
        return base + v // base 被闭包持有，常见逃逸
    }
}
```

## 4. 如何查看逃逸分析结果
可用编译参数查看（在项目根目录执行）：

```bash
go build -gcflags="-m" .
```

常见输出关键词：
- `moved to heap`
- `escapes to heap`

注意：逃逸结果和 Go 版本、编译器优化有关，不同版本可能略有差异。

## 5. 对性能优化的实际建议
1. 优先返回值而不是返回指针（在语义允许时）。
2. 避免把短生命周期对象不必要地放进 `interface{}`。
3. 谨慎使用闭包捕获大对象或高频局部变量。
4. 热路径（高频调用路径）结合基准测试和 `-gcflags="-m"` 一起分析。
5. 不要为“零逃逸”牺牲可读性，先定位瓶颈再优化。

## 6. 小结
逃逸分析不是“越少越好”的教条，而是帮助我们理解内存分配位置。真正的优化目标是：
- 在性能敏感路径中减少不必要堆分配
- 在保持代码清晰的前提下取得更好性能
